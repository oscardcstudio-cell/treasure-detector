#### (OLD) Types ↔ Database Schema ↔ Sync Conversion** ⚠ **FAIL** [SUPERCEDED]

**The Bug**: Session.detector object flattening mismatch. [ARCHIVED FOR REFERENCE]

**Evidence Chain**:

1. **Contract & Types** (`src/db/types.ts`, line 41–44):
   ```typescript
   detector?: {
     model: string;      // e.g. "Garrett ACE 250"
     settings?: string;  // e.g. "All-Metal, sensibilité 6"
   };
   ```
   → Nested object, 2 fields.

2. **SQL Schema** (`supabase/migrations/20260808_001_initial_schema.sql`, line 21–22):
   ```sql
   detector_model TEXT,
   detector_settings TEXT,
   ```
   → Flattened: two separate columns.

3. **Sync Code** (`src/sync/push.ts`, line 240–262):
   ```typescript
   const keyMap: Record<string, string> = {
     detectorModel: 'detector_model',      // ← expects detectorModel (flat)
     detectorSettings: 'detector_settings', // ← expects detectorSettings (flat)
   };
   ```
   → Expects `detectorModel` and `detectorSettings` as **top-level camelCase fields**, NOT nested.

4. **The Problem**: When `convertToRow()` processes a Session with `detector: { model, settings }`:
   - The keyMap looks for `entity.detectorModel` — **does not exist**.
   - The keyMap looks for `entity.detectorSettings` — **does not exist**.
   - The nested `detector` object is **copied as-is** (line 271–274: "copy remaining fields").
   - Result: Row sent to Supabase has `{"detector": {...}}`, not `{"detector_model": "...", "detector_settings": "..."}`.
   - **Supabase rejects or silently drops the nested object**.

5. **Test Gap**: No test of Session sync.
   - `src/sync/__tests__/push.test.ts` tests only `trackPoint` and `digPoint`.
   - Line 88–91: Test payload is `{ id, coord, accuracyM }` — no detector object.
   - Line 141–149: Test payload again has no detector.
   - **No test covers `enqueueSync('session', ..., { detector: { model, settings } })`**.

6. **Impact Field Evidence**:
   - Test in `src/finds/__tests__/finds.test.ts` (line 133) **creates a Session with detector**:
     ```typescript
     detector: { model: 'Garrett ACE 250', settings: 'All-Metal' }
     ```
   - But that test **does not sync** — it only exports/imports locally.
   - When real usage syncs a Session, the detector data **will be lost**.

**Root Cause**: Contract specifies nested `detector` object, SQL schema demands flat columns, sync code is written for flat camelCase fields. Mismatch not caught by tests because no test syncs a Session with detector.
